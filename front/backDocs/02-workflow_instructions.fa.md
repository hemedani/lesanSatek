# راهنمای جامع تست — فرانت‌اند لسان‌ساتک (LesanSatek)

## پیش‌نیازها

### ۱. راه‌اندازی بک‌اند (Deno)

```bash
cd /Users/syd/work/sitak/lesanSatek/back
deno task bc-dev
```

پلی‌گراند API در آدرس `http://localhost:1370/playground` در دسترس است.  
(فایل `.env.local` فرانت‌اند بک‌اند را روی پورت ۱۳۷۰ انتظار دارد.)

### ۲. راه‌اندازی فرانت‌اند (Next.js)

```bash
cd /Users/syd/work/sitak/lesanSatek/front
pnpm dev
```

برنامه در آدرس `http://localhost:3000` قابل دسترسی است.

### ۳. پر کردن پایگاه داده

مجموعه تست `e2e.json` را از طریق پلی‌گراند در `http://localhost:1370/playground` اجرا کنید.  
هر ورودی از `back/http/e2e.json` را به‌ترتیب جایگذاری کنید، یا از اجراکننده مجموعه استفاده کنید.

این مجموعه **۱۲۶ رکورد** ایجاد می‌کند که چرخه کامل حیات را پوشش می‌دهد. در زیر مرجع کامل آمده است.

- **فرآیند خودحل‌شونده**: فرآیند #۲ (حوزه واحد، واحد خرید)

## ۴. تست جریان درخواست خرید (خرید مستقیم از فروشگاه)

این گردش اصلی کسب‌وکار است: **پیش‌نویس درخواست خرید ← افزودن کالا/ثبت ← تأیید مرحله‌ای توسط رئیس واحد ← نهایی‌سازی توسط رئیس سازمان ← تحویل توسط رئیس فروشگاه ← رسید کالا ← پرداخت**.

### ۴-الف. ایجاد پیش‌نویس درخواست خرید (متقاضی)

۱. **خروج** از حساب، ورود با `ali@lesansatek.com` / `password123`
۲. رفتن به فرم ایجاد درخواست خرید
۳. پر کردن:

- عنوان: `خرید کیت TSH` (یا هر عنوان دلخواه)
- توضیحات: `درخواست فوری کیت‌های TSH`
- تعداد: `۱۰`
- مدل کالا: جستجوی `کیت TSH` و انتخاب آن
- **بدون `estimatedAmount`، `budgetLineId`، `processId` یا `storeId`** — این‌ها بعداً تنظیم می‌شوند یا خودحل می‌شوند
- **بدون فیلد `requestingUnit` در `add`** — به‌طور خودکار از حوزه نقش فعال استخراج می‌شود
  ۴. کلیک "ثبت پیش‌نویس درخواست"
  ۵. **تأیید:**
- پیام: "پیش‌نویس درخواست خرید با موفقیت ثبت شد"
- درخواست خرید با وضعیت **"Draft" (پیش‌نویس)** ظاهر می‌شود
- هنوز فرآیندی متصل نیست
- `selectionType` برابر با `"none"` است
- `stuffStatus` برابر با `"none"` است

### ۴-ب. تخصیص کالا به درخواست خرید (رئیس واحد/مدیر سیستم)

۴. انتخاب کالای کیت TSH (موجودی فروشگاه نمونه با قیمت ۲,۸۰۰,۰۰۰ ریال)
۵. **تأیید:**

- `selectionType` ← `"stuff"`
- `stuffStatus` ← `"assigned"`
- `estimatedAmount` برابر با قیمت کالا × تعداد تنظیم می‌شود
- تاریخچه ورودی `"stuff_assigned"` را نشان می‌دهد

## ۱۷. مشکلات متفرقه

- `estimatedAmount` در لحظه **تخصیص کالا** (قیمت کالا × تعداد) یا **انتخاب پیشنهاد** (قیمت پیشنهاد × تعداد) تنظیم می‌شود.
- `unitId` هنگام ایجاد درخواست خرید (**ثبت درخواست**) تنظیم می‌شود، نه هنگام ایجاد پیش‌نویس. در ایجاد پیش‌نویس، `unitId` توسط بک‌اند از حوزه نقش فعال استخراج می‌شود (کاربر آن را تنظیم نمی‌کند).
- برای **رسید کالا**، `receivingUnitId` باید با `requestingUnit._id` درخواست خرید مطابقت داشته باشد (اگر متقاضی تأیید می‌کند) یا واحد انبار باشد.
- یک درخواست خرید **تکمیل شده** قابل حذف نیست.
- **بایگانی فرآیند:** وضعیت ← `"archived"`، نسخه ← `1`، قابل فعال‌سازی مجدد.
- **وضعیت فروشگاه** (`storeStatus`): `active` / `inactive`. فروشگاه غیرفعال نمی‌تواند کالا ارائه دهد.
- **وضعیت کالا** (`stuffStatus`): `none` ← `assigned` ← `ready_to_ship` ← `shipped` ← `delivered` ← `received`.
- **وضعیت مناقصه** (`tenderStatus`): `open` ← `closed` ← `awarded`.
- **وضعیت پیشنهاد** (`offerStatus`): `submitted` ← `accepted` / `rejected`.
- **وضعیت حواله پرداخت** (`paymentOrderStatus`): `pending_payment` ← `sent_to_finance` ← `paid`.
- **محدودیت واحد مالی:** هر کاربر فقط حواله‌های پرداختی که `financeUnitId` با واحد او مطابقت دارد را می‌بیند.
- **بازنشانی رمز عبور** (`user.forgotPassword`): کاربر ایمیل دریافت می‌کند (در حالت توسعه: در `back/tokens/` ذخیره می‌شود). توکن را از فایل کپی کنید.
- **آپلود فایل:** فایل‌ها در `back/uploads/` ذخیره می‌شوند، در URL `http://localhost:1370/uploads/filename.ext` قابل سرویس‌دهی هستند.
- **اعتبارسنجی `addStuff`:** کالا باید متعلق به فروشگاه با `storeStatus = "active"` باشد. `stuffStatus` فروشگاه باید `"active"` باشد. خریدار **نام فروشگاه را نمی‌بیند** — فقط کالا و قیمت را می‌بیند.

## ۱۸. نکات تست (توسعه‌دهنده)

۱. **تغییر مسیر ورود:** الگوی URI نقش (`/admin`, `/unit-head`, `/store`, `/finance`, `/orghead`). اگر نقش تکی است ← تغییر مسیر مستقیم. اگر نقش‌های متعدد است ← بنر + تغییر مسیر /dashboard پیش‌فرض.
۲. **تغییر نقش:** کاربر می‌تواند با انتخاب نقش از منوی کشویی درون برنامه، نقش فعال را تغییر دهد.
۳. **خطوط فرمان curl (برای اشکال‌زدایی مستقیم API):**

```bash
# ورود
curl -X POST http://localhost:1370/api/main/user/login   -H "Content-Type: application/json"   -d '{"email": "admin@lesansatek.com", "password": "password123"}'

# دریافت توکن از پاسخ و ذخیره
TOKEN="<token_from_response>"

# درخواست با توکن (به‌عنوان هدر "token")
curl http://localhost:1370/api/main/purchasingRequest/gets   -H "Content-Type: application/json"   -H "token: $TOKEN"   -d '{"page": 1, "limit": 20, "get": {"_id": 1, "title": 1, "status": 1}}'
```

۴. **خطاهای رایج:**

- `"Token not valid"` ← توکن منقضی شده یا نامعتبر است. دوباره وارد شوید.
- `"Process not found"` ← `processId` نامعتبر است یا فرآیند فعال نیست.
- `"Store not found"` ← `storeId` به فروشگاه غیرفعال یا حذف شده اشاره دارد.
- `"You cannot place items in this store's stuff"` ← فروشنده `canAssignItemToOrder` ندارد.
- `"Insufficient budget"` ← `remainingBudget` برای تعهد کافی نیست.

## ۲۳. مدیریت نقش‌ها (Role Management)

> **نقش‌ها فقط از طریق `addOrRemoveRoles` مدیریت می‌شوند** — `addUser` دیگر فیلد `roles` را نمی‌پذیرد. همه کاربران با نقش پیش‌فرض `[{name: "Ordinary"}]` ایجاد می‌شوند و مجموعه نقش کامل آنها از طریق فراخوانی‌های `addOrRemoveRoles` اعمال می‌شود.
>
> **تغییرات کلیدی مدل:**
>
> - `user.organization` (رابطه تکی) ← `user.organizations` (رابطه چندتایی، آرایه)
> - `user.headedUnit` / `user.headedOrganization` — **حذف شده**. برای یافتن واحدهای تحت سرپرستی: نقش‌های کاربر را برای ورودی‌های `UnitHead` جستجو کنید یا `unit.gets` را با `{ "head._id": userId }` پرس‌وجو کنید
> - **تخصیص دو مرحله‌ای رئیس واحد:** `unit.updateRelations` رابطه رئیس را تنظیم می‌کند، سپس `user.addOrRemoveRoles` نقش `UnitHead` را اضافه می‌کند + `user.units` را همگام‌سازی می‌کند
> - **نقش OrgHead:** `scopeType: "organization"`، `scopeId: <orgId>`
> - **نقش StoreHead:** `scopeType: "store"`، `scopeId: <storeId>`
